# Как запустить проект с нуля

Приложение «Память новомучеников» написано на React Native + Expo (SDK 58) и работает на iOS, Android и в браузере.

## Что можно запустить на вашем компьютере

| Платформа                      | macOS | Windows | Linux   |
| ------------------------------ | ----- | ------- | ------- |
| Веб (в браузере)               | да    | да      | да      |
| Android (эмулятор или телефон) | да    | да      | да      |
| iOS (симулятор или iPhone)     | да    | **нет** | **нет** |

iOS-версию можно собрать только на Mac. Если у вас Windows или Linux, работайте с вебом и Android.

> **Expo Go не подойдёт.** В проекте есть нативные модули (карта MapLibre и другие), которых нет внутри Expo Go. Поэтому приложение собирается само: шаги 7 и 8. Если отсканировать QR-код в Expo Go, приложение упадёт с ошибкой, и это нормально.

## Шаг 1. Установить Git

Проверьте, установлен ли Git:

```bash
git --version
```

Если команда не найдена, установите Git по инструкции для вашей системы: <https://git-scm.com/install>

- **macOS:** при первом вызове `git --version` система сама предложит поставить Command Line Tools. Согласитесь.
- **Windows:** скачайте установщик и ставьте с настройками по умолчанию.
- **Linux:** `sudo apt install git` (Ubuntu/Debian).

При первом использовании представьтесь Git:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "ваша@почта"
```

## Шаг 2. Базовые программы

### Node.js

Нужна версия **22.13 или новее** (подойдут 22.x и 24.x). Скачайте LTS-версию с <https://nodejs.org> и установите.

Проверка:

```bash
node -v   # v22.13.0 или выше
npm -v
```

### Редактор кода

Рекомендуем **Visual Studio Code**: <https://code.visualstudio.com>.

## Шаг 3. Скачать проект

Исходный код проекта находится в публичном репозитории: <https://github.com/ddybka/pstgu-new-martyrs-app>. Зарегистрируйтесь на <https://github.com>, если аккаунта ещё нет.

Склонируйте репозиторий и перейдите в папку приложения:

```bash
git clone https://github.com/ddybka/pstgu-new-martyrs-app.git
cd pstgu-new-martyrs-app/app
```

> **Важно:** весь код приложения лежит в папке `app/`. Все команды ниже выполняются **из неё**.

## Шаг 4. Установить зависимости

```bash
npm install
```

## Шаг 5. Ввести доступы к API

Приложение берёт данные из API базы «За Христа пострадавшие» (`api.nmbook.ru`), и для этого ему нужны логин и пароль. **В репозитории их нет**, и добавлять их туда нельзя: репозиторий публичный. Доступы хранятся в файле `app/.env.local`, который Git не отправляет на GitHub.

Без этого файла приложение запустится, но вместо списка новомучеников покажет ошибку «Приложение собрано без доступа к базе данных».

### Способ 1. Получить значения у руководителя проекта

1. Попросите логин и пароль у администратора БД. Пересылайте их только в личных сообщениях, не в общих чатах и не в задачах на GitHub.
2. В папке `app/` создайте файл `.env.local` из шаблона:

   ```bash
   # macOS и Linux
   cp .env.example .env.local

   # Windows (командная строка)
   copy .env.example .env.local
   ```

3. Откройте `.env.local` в редакторе и впишите значения после знака `=`, без кавычек и пробелов:

   ```bash
   EXPO_PUBLIC_API_URL=https://api.nmbook.ru/
   EXPO_PUBLIC_API_LOGIN=логин
   EXPO_PUBLIC_API_PASSWORD=пароль
   ```

### Способ 2. Скачать из Expo (если вас добавили в проект на expo.dev)

Те же значения хранятся в настройках проекта на Expo. Если у вас есть к нему доступ, файл создаётся одной командой:

```bash
npx eas-cli login
npx eas-cli env:pull --environment development
```

Команда сама создаст `app/.env.local`.

### Что важно помнить

- Файл `.env.local` **нельзя коммитить**. Он уже есть в `.gitignore`, поэтому `git add .` его не захватит. Не убирайте его оттуда и не переименовывайте файл в другое имя.
- Если поменяли значения в `.env.local`, перезапустите сервер разработки с очисткой кэша: `npx expo start -c`. Значения вшиваются в приложение при запуске, и без перезапуска останутся старые.
- Для сборок через EAS (`eas build`) ничего делать не нужно: там доступы берутся из настроек проекта на expo.dev, а не из вашего файла.
- Логин и пароль всё равно попадают внутрь собранного приложения, и при желании их можно оттуда достать. Файл `.env.local` нужен, чтобы они не лежали в публичном репозитории, а не чтобы скрыть их от пользователей.

## Шаг 6. Запуск в браузере (самый быстрый способ)

```bash
npm run web
```

Откроется браузер с приложением, обычно по адресу <http://localhost:8081>. Если не открылся, нажмите `w` в терминале.

Для начала работы этого достаточно: большая часть экранов выглядит так же, как на телефоне.

## Шаг 7. Запуск на Android

### 7.1. Установить Android Studio

1. Скачайте с <https://developer.android.com/studio> и установите.
2. При первом запуске выберите **Standard** и дождитесь, пока скачается Android SDK.
3. Откройте **More Actions > SDK Manager** (или Settings > Languages & Frameworks > Android SDK):
   - на вкладке **SDK Platforms** отметьте свежую версию Android (API 36 или 37);
   - на вкладке **SDK Tools** проверьте, что отмечены *Android SDK Build-Tools*, *Android SDK Platform-Tools*, *Android Emulator*.
   - Нажмите **Apply**.

Недостающие компоненты (NDK, нужную версию Build-Tools) сборка докачает сама при первом запуске.

### 7.2. Прописать переменные окружения

Сборке нужно знать, где лежат Android SDK и Java. Java уже входит в Android Studio.

**macOS** — добавьте в конец файла `~/.zshrc`:

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

Затем выполните `source ~/.zshrc` или перезапустите Терминал.

**Windows** — Пуск > «Изменить системные переменные среды» > «Переменные среды» > создайте переменные пользователя:

- `ANDROID_HOME` = `C:\Users\<имя>\AppData\Local\Android\Sdk`
- `JAVA_HOME` = `C:\Program Files\Android\Android Studio\jbr`
- в `Path` добавьте `%ANDROID_HOME%\platform-tools` и `%ANDROID_HOME%\emulator`

После этого перезапустите терминал и VS Code.

**Linux** — то же, что на macOS, но SDK обычно лежит в `$HOME/Android/Sdk`, а Java — в папке `jbr` внутри Android Studio.

Проверка: команда `adb --version` должна вывести версию.

### 7.3. Эмулятор или свой телефон

- **Эмулятор:** в Android Studio откройте **Device Manager > Create Virtual Device**, выберите, например, Pixel, и образ системы с API 36. Запустите эмулятор кнопкой запуска (Run) напротив него.
- **Свой телефон:** Настройки > О телефоне > семь раз нажмите на «Номер сборки», чтобы включить режим разработчика. Затем в «Для разработчиков» включите **Отладку по USB** и подключите телефон кабелем. Разрешите отладку во всплывающем окне на телефоне. Команда `adb devices` должна показать устройство.

### 7.4. Собрать и запустить

```bash
npm run android
```

Первая сборка долгая, **10–30 минут**: скачивается Gradle и нативные библиотеки. Следующие сборки идут намного быстрее. Когда сборка закончится, приложение само откроется на эмуляторе или телефоне.

## Шаг 8. Запуск на iOS (только macOS)

### 8.1. Установить Xcode

1. Установите **Xcode** из App Store. Он большой, около 10–15 ГБ, скачивание долгое.
2. Запустите Xcode один раз, примите лицензию и согласитесь установить дополнительные компоненты.
3. В **Xcode > Settings > Components** скачайте свежий **iOS Simulator**.
4. Выполните в Терминале:

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

### 8.2. Установить CocoaPods

CocoaPods ставит нативные библиотеки для iOS. Удобнее всего через Homebrew:

```bash
# Homebrew, если его ещё нет (https://brew.sh):
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install cocoapods
```

### 8.3. Собрать и запустить

```bash
npm run ios
```

Первая сборка занимает **10–20 минут**. По её окончании сам откроется симулятор iPhone с приложением.

**На свой iPhone:**

1. Подключите телефон кабелем.
2. В Xcode > Settings > Accounts войдите со своим Apple ID. Платный аккаунт разработчика для этого не нужен.
3. Запустите:

```bash
npx expo run:ios --device
```

4. Выберите телефон из списка.
5. При первом запуске на iPhone откройте Настройки > Основные > VPN и управление устройством и доверьте своему профилю разработчика. На iOS 16+ также включите Настройки > Конфиденциальность и безопасность > **Режим разработчика**.

Приложение, подписанное бесплатным Apple ID, работает 7 дней. Потом его нужно собрать заново.

## Как работать каждый день

Собирать приложение заново каждый раз не нужно. Достаточно запустить сервер разработки:

```bash
cd app
npm start
```

Дальше нажмите в терминале:

- `w` — открыть в браузере;
- `a` — открыть на Android (собранное приложение уже должно стоять на эмуляторе или телефоне);
- `i` — открыть в симуляторе iOS;
- `r` — перезагрузить приложение;
- `j` — открыть отладчик.

Изменения в коде (`src/`) появляются в приложении сразу после сохранения файла.

**Пересобирать** (`npm run android` / `npm run ios`) нужно только в двух случаях:

- после `npm install` новой библиотеки с нативным кодом;
- после изменения `app.json` или папки `plugins/`.

Если сомневаетесь, лучше пересоберите.

## Архитектура проекта

```
app/
├── src/
│   ├── app/               экраны; имя файла – адрес экрана (Expo Router)
│   │   ├── (tabs)/        вкладки: Сегодня, Календарь, Карта, Поиск
│   │   └── person/        карточка новомученика
│   ├── components/        переиспользуемые части интерфейса
│   ├── hooks/             загрузка данных (персоналии, точки карты, фото)
│   ├── utils/             запросы к API, кэш, хранилище
│   ├── constants/         тема, адреса
│   └── data/              снимки точек карты и списка имён для поиска без сети
├── assets/                иконки, картинки
├── plugins/               доработки нативных проектов при сборке
├── scripts/               служебные скрипты
├── .env.example           шаблон доступов к API (сами доступы — в .env.local)
├── app.json               настройки приложения Expo
└── package.json           зависимости и команды
```

Файлы с расширением `.web.tsx`, `.ios.tsx`, `.android.tsx` — версии компонента для конкретной платформы. Expo сам выбирает нужную.

Папки `ios/` и `android/` **генерируются автоматически** при сборке и в Git не попадают. Руками их не правим: все изменения вносим через `app.json` и `plugins/`.

## Полезные команды

| Команда                                          | Что делает                                  |
| ------------------------------------------------ | ------------------------------------------- |
| `npm start`                                      | сервер разработки                           |
| `npm run web`                                    | запуск в браузере                           |
| `npm run android`                                | сборка и запуск на Android                  |
| `npm run ios`                                    | сборка и запуск на iOS                      |
| `npm run lint`                                   | проверка кода линтером                      |
| `npx expo start -c`                              | запуск с очисткой кэша сборщика             |
| `npx eas-cli env:pull --environment development` | скачать доступы к API в `.env.local`        |
| `npx expo prebuild --clean`                      | заново сгенерировать `ios/` и `android/`    |
| `node scripts/build-map-points.mjs`              | обновить снимок точек карты с map.nmbook.ru |
| `node --env-file=.env.local scripts/build-persons-index.mjs` | обновить список имён для поиска без сети |
